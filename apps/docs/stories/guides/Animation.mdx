# Animation in greese ui

greese ui animates on three levels, from least to most code:

| Level                            | What                                                                                                            | Costs                                                                          |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **The `greese` prop**            | Presets and options on any component: entrances, scroll reveals, hover/press/focus, text effects, overlay exits | Presets: CSS only. Interactions and text: a small runtime, loaded on first use |
| **`<Motion>` and `useGreese()`** | The prop for any element; greese.js tied to a component's lifetime                                              | The same, plus what you build                                                  |
| **greese.js directly**           | Full timelines, re-exported from `@greese/react`                                                                | About 5.6 kB, only if imported                                                 |

The live demos are under **Motion/greese prop** and **Motion/greese.js**.
greese.js on its own, in every install form, is covered in
**Guides/greese.js**.

## Do you need any of it?

Components already animate their own states (menus, dialogs, toasts,
tooltips) with CSS. That runs off the main thread, and the `--greese-duration-*`
tokens collapse it under reduced motion. Add motion where it helps
someone follow what changed, not everywhere.

## The `greese` prop

Every greese ui component that draws something accepts `greese`. That's all of
them except Slot, VisuallyHidden, Break, Spacer, Show/Hide, ThemeProvider and
Toaster; a type check in the build enforces it.

```tsx
<Card greese="fadeUp" />                                     // enter preset
<Card greese={{ inView: 'fadeUp' }} />                       // when scrolled into view
<Stack greese={{ enter: 'fadeUp', stagger: 0.05 }}>…</Stack> // children in turn
<Button greese={{ hover: 'rise', press: 'squish' }} />       // interaction feedback
<Heading greese={{ text: 'split' }}>Served fast</Heading>    // text effects
<Dialog greese={{ enter: 'pop', exit: 'scaleOut' }} … />     // overlay enter and exit
<Card greese="fadeIn+scaleIn,+2,fadeOut" />                  // a sequence of effects
<Card greese="fadeUp,wobble" />                              // with your own effect
```

### Options

| Option                    | Values                                                                                                                                                                | Needs JavaScript?             |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `enter`                   | An effect, a [sequence](#composing-effects), or greese.js keyframes                                                                                                   | A preset alone: no. Else: yes |
| `inView`                  | The same; plays once wholly in view, clear of the bottom 10% of the viewport (taller elements: half the viewport). Elements already in view stay as they are          | Yes (an IntersectionObserver) |
| `once`                    | `inView` plays only the first time (default `true`)                                                                                                                   |                               |
| `exit`                    | An effect: how an overlay (Dialog, Popover, Menu, Tooltip) leaves. It fades, and moves and scales to where the effect ends (`'fadeOutUp'`, `'scaleOut'`, `'rise'`…)   | No                            |
| `hover`, `press`, `focus` | Usually `'rise'`, `'squish'`, `'tilt'`, `'glow'`; any effect, sequence or keyframes. Plays and reverses; interruptible. Hover ignores touch                           | Yes                           |
| `text`                    | `'type'`, `'count'`, `'split'`; `type` and `split` keep markup inside (links stay links), `count` takes a plain number                                                | Yes                           |
| `duration`, `delay`       | Seconds. `duration` applies to each effect and overrides an effect's own. Defaults: 0.5 for entrances, 0.2 for interactions                                           |                               |
| `ease`                    | Any greese.js ease. `linear`, `in`, `out`, `inOut`, the CSS keywords and bézier arrays stay CSS-only; others (`elastic.out`…) switch the entrance to JavaScript       |                               |
| `distance`                | How far the travelling effects go (`fadeUp`, `fadeDown`, `fadeStart`, `fadeEnd`, `fadeOutUp`, `fadeOutDown`; default `'1rem'`). A call's own `distance` argument wins |                               |
| `stagger`                 | Seconds between children: animates the children instead of the element                                                                                                |                               |
| `scope`                   | `true` or `{ stagger, delay, inView, replay }`: orders every `enter` inside this element, at any depth (see Scopes)                                                   | No (a small lazy chunk)       |
| `timeline`                | `(tl, el) => void`: fill a greese.js timeline yourself. It plays on enter, or on reveal with `inView`                                                                 | Yes                           |

### Scopes: ordering the entrances inside a parent

`stagger` animates a parent's direct children. A **scope** orders every entrance
inside it, however deep, as one sequence:

```tsx
<Stack greese={{ scope: { stagger: 0.1, delay: 0.2 } }}>
  <Heading greese={{ enter: 'fadeUp' }}>Title</Heading>
  <Text greese={{ enter: 'fadeUp' }}>Intro</Text>
  <Grid greese={{ scope: { stagger: 0.05 } }}>
    {cards.map((c) => (
      <Card greese={{ enter: 'scaleIn' }}>…</Card>
    ))}
  </Grid>
</Stack>
```

Each member declares only its own entrance; the scope gives it a start time:
`delay + position × stagger`, in document order. A scope inside a scope takes
one position in the outer one and its members start from there, so a section's
contents play as a block in the page's sequence. `inView: true` holds the whole
scope until it scrolls into view. `replay` plays the scope again in place, without remounting: change it (a counter a Replay button bumps) and every entrance restarts. Members still use their own `duration`,
`ease` and `delay` (which adds to the start time).

It's opt-in on purpose. A scope is a client component that loads a small lazy
chunk (under 1 kB), and nothing else changes: components without one pay
nothing, and the entrances are the same CSS animations, so reduced motion and
server components behave as before. Things to know:

- Members are the entrances present when the page renders; children added
  later play as they appear, unordered.
- With server rendering, entrances begin at first paint, before the page is
  interactive; a scope sets their start times when it hydrates. Use `inView`
  for sections below the fold, or the `@greese/react/greese` import so start
  times are set before the first frame.
- Scroll reveals (`inView` on a member) keep their own trigger and aren't
  ordered by a scope.

### Effects

Effect names are camelCase. Every effect is defined once, in `@greese/ui`
(`src/effects/definitions.ts`), in two groups:

- **Base effects** animate one property each, and take optional parameters. Every
  parameter has a default, so you name only what you change.
- **Combo effects** are made of base effects, each placed in time as a share of
  the combo (`popIn` is `pop` plus a `fadeIn` over its first 60%).

| Group | Effect                                                                                   | Animates                                                                                                                                               | Parameters (defaults)                                                                 |
| ----- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Base  | `fadeIn`, `fadeOut`                                                                      | opacity                                                                                                                                                | `start`, `end` (`0`→`1`, `1`→`0`)                                                     |
| Base  | `scaleIn`, `scaleOut`                                                                    | scale                                                                                                                                                  | `start`, `end` (`0`→`1`, `1`→`0`)                                                     |
| Base  | `blurIn`, `blurOut`                                                                      | blur, in px                                                                                                                                            | `start`, `end` (`8`→`0`, `0`→`8`)                                                     |
| Base  | `slideUp`, `slideDown`, `slideRight`, `slideLeft`                                        | translation (physical directions)                                                                                                                      | `start`, `end` (`'100%'`→`'0%'`, `'-100%'`→`'0%'`, `'-100%'`→`'0%'`, `'100%'`→`'0%'`) |
| Base  | `pop`                                                                                    | a springy scale                                                                                                                                        | `start` `1`, `end` `1`, `peak` `1.075`, `peakAt` `0.6`                                |
| Base  | `squish`, `tilt`, `glow`                                                                 | scale, rotation, brightness                                                                                                                            | `start`, `end` (`1`→`0.96`, `0`→`-2`, `1`→`1.12`)                                     |
| Base  | `wipe<Dir>`: `Right`, `Left`, `Up`, `Down`, `DownRight`, `DownLeft`, `UpRight`, `UpLeft` | a mask: the edge sweeps that way, revealing the element                                                                                                | `start`, `end` (the mask's sizes)                                                     |
| Base  | `wipeOut<Dir>`, the same eight                                                           | a mask: the edge sweeps that way, covering it (leaves)                                                                                                 | `start`, `end`                                                                        |
| Base  | `wipeOpenX`, `wipeOpenY`, `wipeCloseX`, `wipeCloseY`                                     | a mask from or to the middle, across or down                                                                                                           | `start`, `end`                                                                        |
| Base  | `irisIn`, `irisOut`                                                                      | an opening in the element's proportions, from or to the middle                                                                                         | `start`, `end` (the mask's sizes: `0% 0%`→`142% 142%`, just past the corners)         |
| Base  | `iris<Dir>`, `irisOut<Dir>`, the same eight                                              | an opening that closes toward that side or corner; arriving, it opens from there: its exit reversed                                                    | `start`, `end`                                                                        |
| Combo | `fadeUp`, `fadeDown`, `fadeStart`, `fadeEnd`                                             | fade + a slide of `distance` (`fadeStart`/`fadeEnd` follow the writing direction)                                                                      | `distance` (`1rem`)                                                                   |
| Combo | `fadeOutUp`, `fadeOutDown`                                                               | fade out + a slide of `distance`                                                                                                                       | `distance` (`1rem`)                                                                   |
| Combo | `popIn`, `popOut`                                                                        | pop + a fade                                                                                                                                           | `start`/`end`, `peak`, `peakAt`                                                       |
| Combo | `pocket<Dir>`, `pocketOut<Dir>`, the same eight                                          | rises out of (or sinks into) a slot at its own edge: a slide and a wipe in step                                                                        | `distance` (`'100%'`: its whole size, so it starts or ends out of sight)              |
| Combo | `rise`, `fall`                                                                           | a lift or drop + a scale                                                                                                                               | `lift` `-4` / `drop` `4` (px), `scale` `1.02` / `0.98`                                |
| Base  | `turnX`, `turnY`, `hinge`, `depth`                                                       | a turn about the horizontal or vertical axis (`hinge`: about the top edge), or a move along the line of sight, as `transform` with its own perspective | `start`, `end` (degrees; px for `depth`)                                              |
| Combo | `flipUp`, `flipDown`, `flipLeft`, `flipRight`, and `flipOut<Dir>`                        | turns into place from 75° toward the way it arrives (and back out the same way), with a fade                                                           | `angle` (`75`)                                                                        |
| Base  | `flipOver<Dir>`, `flipOverOut<Dir>`, the same four                                       | half a turn, a panel's two faces: arriving from its back, leaving to it, the same way, its back face hidden (a pair is a card turning over)            | `start`, `end` (degrees: `±180`→`0`, `0`→`±180`)                                      |
| Combo | `depthIn`, `depthOut`                                                                    | rises out of the page from behind it, or sinks back in, with a fade                                                                                    | `depth` (`-240`, px)                                                                  |
| Combo | `swingIn`, `swingOut`                                                                    | swings down from its top edge like a sign, or back up                                                                                                  | `angle` (`-80`)                                                                       |
| Yours | Anything defined with [`defineGreeseEffect()`](#custom-effects) or in Theme Studio       |                                                                                                                                                        | `duration`, `offset`, `ease`                                                          |

Wipes, irises and pockets animate a **mask**, never `clip-path`: the clip
belongs to an element's shape (ADR 0024), and a mask composes with it. The mask
exists only while the effect plays. Each arrives and leaves (`wipeRight` and
`wipeOutRight`, `irisUp` and `irisOutUp`, `pocketUp` and `pocketOutUp`), in eight
directions; wipes and irises also from or to the middle. Leaving ones are
overlay exits too (`<Dialog greese={{ exit: 'pocketOutDown' }}>`): an exit sets
everything an overlay moves to, so what it doesn't move stays put, and the
overlay holds the mask as it closes, from the size the mask starts at.

Flips, swings and depth are three-dimensional: they animate `transform`, with
its own `perspective()`, so they foreshorten anywhere, need no `perspective` on
a parent, and compose with the `translate`, `rotate` and `scale` the other
effects animate. An overlay can leave with one too: its exit carries the
`transform` (and, for a swing, the pivot).

A built-in always does what its name says. Motion themes don't change effects:
they choose which one plays where (the `'theme'` entrance, tab panels, table
rows, overlays; see Theming, ADR 0025).

`greese="theme"` (or `{ enter: 'theme' }`, `{ inView: 'theme' }`) plays whatever
entrance the theme assigns, `fadeUp` in the base theme. Use it for general
reveals, so a page arrives the way its theme does; name an effect where the
motion means something.

There is no list of "entrance" or "leaving" effects, because the kind of an
effect is where it ends:

- an effect that ends at the element's resting state (opacity 1, no offset, no
  scale) is a **CSS preset** when played alone: `greese="fadeUp"` is plain CSS;
- one that ends away from it (`fadeOut`, `rise`, `scaleOut`…) runs in the
  runtime, and an overlay can **leave** with it: `exit` takes the `translate`
  and `scale` where the effect ends, and fades.

Any effect works in any slot (`enter`, `inView`, `hover`, `press`, `focus`):
`hover: 'pop'` is allowed, if unusual. An effect that ends hidden (`fadeOut`)
stays hidden.

### Composing effects

A sequence is one string:

- **`+`** plays effects at the same time;
- **`,`** separates groups, and each group starts when the previous one ends;
- **a number** (`2`, `+2`, `0.5`) is a pause, in seconds; a **negative** one (`-0.2`) backs the next step up, so it overlaps the one before: `slideUp,-0.2,popIn`.

```tsx
<Card greese="fadeIn+scaleIn,+2,fadeOut" />           // in together, wait 2 s, fade out
<Card greese={{ enter: 'fadeUp,pop', duration: 0.3 }} /> // each effect 0.3 s
<Stack greese={{ inView: 'fadeStart+blurIn', stagger: 0.05 }}>…</Stack>
<Button greese={{ hover: 'rise+glow' }} />            // interactions compose too
```

- Sequences run in greese.js, so they load the runtime. A preset on its own
  stays pure CSS.
- `delay` comes before the first group; `stagger` offsets each child within
  every group, and a group ends when its last child finishes.
- The first group's first frames show during `delay`, so nothing flashes.
- Sequences are typed: a single name must be a known effect (typos fail to
  compile), and any string with `+`, `,` or parentheses is accepted as a
  sequence. Unknown names in a sequence are skipped with a console warning.

### Effect arguments

An effect takes arguments in parentheses. Nothing is required: only what you
write changes.

```tsx
<Card greese="fadeIn(0.25, 0.8)" />                 // by position: start, end
<Card greese="fadeIn({ end: 0.8, duration: 1 })" /> // an object: only these keys
<Card greese="fadeIn(end: 0.8)" />                  // or key: value, key=value
<Card greese="fadeUp(2rem)+scaleIn(offset: 0.2)" /> // a combo's own parameter, a timing key
<Card greese="slideUp(calc(1rem + 2px), 0)" />      // commas and + inside parentheses are fine
```

Positional arguments fill the effect's parameters in the order of the table,
then the timing keys, so the signature is
`someEffect(start, end, duration, offset, ease)`. Every effect, base, combo or
yours, takes the timing keys:

| Key        | What                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `duration` | Seconds this effect takes. Wins over the instance's `duration`, which wins over the effect's own default                         |
| `offset`   | Seconds after its step starts. Inside a `+` group it staggers one effect from the others; a group ends when its last effect does |
| `ease`     | A greese.js ease for this effect. Wins over the instance's `ease`                                                                |

Arguments make the runtime play the effect, since CSS can't take them. Inside a
combo the base effects have their own timing, as shares of the combo (a
`popIn`'s fade covers its first 60%); the combo's `duration` and `offset` move
all of it.

### Custom effects

Define an effect once, then use it by name anywhere, alone or in sequences:

```ts
// effects.ts: import it from your client entry (or a 'use client' module)
import { defineGreeseEffect } from '@greese/react'

// Keyframes
defineGreeseEffect('wobble', { rotate: [0, -6, 6, -3, 0] })

// A function of { el, distance, rtl, args }, for effects that adapt;
// `args` holds what the call wrote by name: drift({ amount: '2rem' })
defineGreeseEffect('drift', ({ distance }) => ({
  y: [`calc(${distance} * 3)`, '0rem'],
  opacity: [0, 1],
}))

// Keyframes with their own defaults (a prop's duration/ease still wins)
defineGreeseEffect('spin', {
  keyframes: { rotate: [0, 360] },
  duration: 0.8,
  ease: 'inOut',
})

// Make the names type-check and autocomplete
declare module '@greese/react' {
  interface GreeseEffectRegistry {
    wobble: true
    drift: true
    spin: true
  }
}
```

To read the built-in effects as plain keyframes (to list or edit them, as Theme
Studio's Motion tab does), `describeGreeseEffects(distance?)` resolves to every
name's keyframes at that distance.

```tsx
<Card greese="fadeUp,wobble" />
<Card greese={{ inView: 'drift', distance: '2rem' }} />
<Button greese={{ hover: 'wobble', duration: 0.4 }} />
```

- **Keyframes** are greese.js keyframes: every property greese.js animates
  (individual transforms, CSS, custom properties, colors), arrays per
  property or a list of keyframe objects with `offset` and `ease`.
- **A built-in's name stays the built-in's.** An effect defined under it is never played, and the kit's `effect()` mixin refuses the name, so `fadeUp` fades up under every theme. Give yours a name of its own and assign it where it should play. The kit's `effect()` writes its CSS, for a preset played alone and for an overlay's `exit`: Theme Studio's Motion tab writes both (and copies a built-in to start from), so the kit's `motion(enter:)`, `motion(exit:)` and `motion-defaults()` accept it.
- **Server Components** can use defined effects, because a name is just a
  string. The definition must run on the client before the element mounts:
  call `defineGreeseEffect()` from a module your client bundle imports at
  start-up, not from a Server Component.
- **`exit` takes any effect**, yours too. A built-in's exit is CSS (a class sets
  what it changes). For one from `defineGreeseEffect()` there is no class, so
  the runtime sets the `translate` and `scale` where its keyframes end, on the
  overlay, from the same plan the build makes for the built-ins; it loads the
  runtime, like any effect of your own. Opacity is always faded.
- **Positional arguments** of your own effect fill `duration`, `offset`, `ease`
  (`wobble(0.6)` is a 0.6 s wobble); its other arguments are by name.

### How it stays light

- **CSS presets have no JavaScript.** `greese="fadeUp"` resolves to a class
  and a few custom properties during render. That works in Server
  Components, the first paint is already animating, and nothing flashes.
- **The runtime loads only when needed.** Interactions, scroll reveals, text
  effects, keyframes and timelines need a small runtime plus greese.js
  (about 10.8 kB together). Components load it with a dynamic `import()`, so
  your bundler puts it in its own chunk, fetched the first time a prop needs
  it. A page with no such prop never downloads it.
- **The cost to every component** is about 1.4 kB (brotli), paid once per
  app: the resolver, the client island that attaches the runtime, and the
  names of the effects CSS can play (so a preset never loads the runtime).

### Loading the runtime up front

A JavaScript entrance (keyframes, text effects, timelines) can't start until
the runtime arrives. If that's on the first screen, import it once at your
entry point, so it's in the main bundle and attaches before the first paint:

```ts
// main.tsx, or app/layout.tsx
import '@greese/react/greese'
```

Without it, everything still works; the runtime simply loads on first use.

**Prefer CSS presets on the first screen instead.** Attaching the runtime
before the first paint means the first full style calculation happens inside
a JavaScript task. On the greese ui homepage, with a few dozen animated
elements above the fold, that was most of 650 ms of blocking time on a
throttled phone. With CSS presets (`fadeUp`, `scaleIn`, `pop` and so on, with
`delay` and `stagger`) up top and the runtime left lazy, Total Blocking Time
fell to 20 ms. Hover and press effects attaching a moment later are invisible.

### Server Components and SSR

- Presets and options render on the server: the classes and variables are in
  the HTML, and the animation starts with the first paint.
- Interactions, reveals and text effects attach after hydration.
- `timeline` takes a function, and functions can't cross from a Server
  Component to the client. Use it from a client component (`'use client'`).

### Per-component CSS

With `@greese/react/styles.css`, the presets are included. If you import
per-component stylesheets instead, add the presets once:

```ts
import '@greese/react/css/Motion.css'
```

### Reduced motion

Under `prefers-reduced-motion: reduce`:

- CSS presets don't run, and nothing is ever hidden;
- interactions don't move;
- text stays as written;
- scroll reveals show at once;
- sequences cut from effect to effect with no delay, but pauses still wait,
  so `'fadeIn,+2,fadeOut'` is still readable for two seconds;
- `timeline` jumps to its end (a sequence with a `timeline` too jumps with it).

You don't need to check the media query yourself.

An app with a "Reduce motion" setting of its own gets the same with
`<ThemeProvider motion="reduce">` around the subtree (or
`data-greese-motion="reduce"` on any element, the root included). CSS
durations collapse, nothing animates, transitions or scrolls smoothly, and
the runtime, greese.js and `@greese/react/svg` skip to the end for any element
inside it. `prefersReducedMotion(el)` from `@greese/js` answers the same
question for your own code.

### Tuning motion globally

The presets read CSS custom properties. Override them in your CSS (for
example per brand) and every `greese` prop follows:

```css
:root {
  --greese-ease-out: cubic-bezier(0.2, 0.8, 0.2, 1); /* the default ease */
}
.calm {
  --greese-motion-duration: 0.8s;
  --greese-motion-distance: 0.5rem;
}
```

| Variable                              | Default                                       |
| ------------------------------------- | --------------------------------------------- |
| `--greese-motion-duration`            | `0.5s`                                        |
| `--greese-motion-delay`               | `0s`                                          |
| `--greese-motion-distance`            | `1rem`                                        |
| `--greese-motion-ease`                | `var(--greese-ease-out)`                      |
| `--greese-ease-in`, `-out`, `-in-out` | The power2 curves behind `in`, `out`, `inOut` |

A per-instance option (`greese={{ duration: 0.3 }}`) wins over these.

## `<Motion>`: the prop for any element

```tsx
import { Motion } from '@greese/react'

<Motion greese="fadeUp"><img src={hero} alt="" /></Motion>       // wraps in a <div>
<Motion asChild greese={{ hover: 'rise' }}><a href="/pricing">Pricing</a></Motion>
```

## `useGreese()`: greese.js in a component

greese.js tied to a component's lifetime. It runs your build after mount (refs
are set) and before paint, re-runs it when dependencies change, and reverts
everything on unmount, including animations you start later in event
handlers. Selector strings only match inside `scope`, so two instances of a
component never animate each other.

```tsx
'use client'
import { useRef } from 'react'
import { Button, useGreese } from '@greese/react'

export function Tiles({ items }: { items: string[] }) {
  const root = useRef<HTMLDivElement>(null)
  const { animate } = useGreese(
    (g) => {
      g.timeline().from('.tile', { opacity: 0, y: 16, stagger: 0.05 })
    },
    { scope: root, dependencies: [items.length] }
  )
  return (
    <div ref={root}>
      {items.map((item) => (
        <div key={item} className="tile">
          {item}
        </div>
      ))}
      <Button onClick={() => animate('.tile', { y: [0, -8, 0] }, { duration: 0.4 })}>
        Bounce
      </Button>
    </div>
  )
}
```

`useGreese(build?, dependencies | config)`:

| Config           | What                                                                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `scope`          | A ref. Selector strings passed to the context's methods, and to the timelines it makes, only match inside it                                   |
| `dependencies`   | Re-run the build when these change (default `[]`). Pass the array instead of a config as a shorthand: `useGreese(build, [x])`                  |
| `revertOnUpdate` | On a dependency change, revert the last build before re-running. Default `false`: it's paused where it is, so the new build continues smoothly |

`build` gets a context, `g`, and may return a cleanup function. The hook
returns the same helpers, stable across renders, for use in handlers:

| Helper                           | What                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `timeline(options?)`             | A greese.js timeline: tracked, and its `to`/`from`/`fromTo`/`set`/`animate` are scoped |
| `animate(targets, kf, opts?)`    | Like greese.js `animate()`: plays at once, tracked and scoped                          |
| `select(selector)`               | The matching elements inside `scope`                                                   |
| `contextSafe((g, ...args) => …)` | Wraps a handler so it receives `g` first; the same as using the helpers directly       |

- **Make animations through `g`** (or the returned helpers). A `timeline()`
  or `animate()` imported from greese.js directly isn't tracked, so it isn't
  reverted.
- **Strict Mode** is fine: the first build is reverted before the second.
- **Reverting** restores each property's original computed value as an
  inline style; it doesn't remove the inline style.
- **Server rendering:** the build never runs on the server.

### `useTimeline()`

The one-timeline shortcut, built on `useGreese` (with `revertOnUpdate`). It
returns the timeline, `undefined` until the first build:

```tsx
const box = useRef<HTMLDivElement>(null)
const tl = useTimeline(
  (tl) => tl.animate(box.current, { x: [0, -8, 8, -4, 0] }, { duration: 0.4 }),
  [],
  { paused: true }
)
<Button onClick={() => tl?.restart()}>Try again</Button>
```

## Page transitions

When the page changes, `PageTransition` plays the old page's exit and the new
page's entrance with the same effects, paced by the motion theme. A page
leaves as a snapshot, or live, its members' exits playing in turn. See
[Page transitions](?path=/docs/guides-page-transitions--docs).

## greese.js directly

Everything in **Guides/greese.js** works with greese ui components and
tokens. Animate a token and every component that reads it follows:

```ts
import { timeline } from '@greese/react'

timeline({ repeat: 1, yoyo: true }).to('.promo', {
  '--greese-color-primary': '#e11d48',
  duration: 1,
})
```
