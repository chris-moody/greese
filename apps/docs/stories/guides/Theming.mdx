# Theming

greese ui's look is a set of design tokens. Each one is a CSS custom property
(`--greese-color-primary`, `--greese-space-4`, `--greese-radius-md`, …), and every
component reads them. To theme the library, you change token values. There's
no theme object in React state, no re-render when the theme changes, and no
CSS-in-JS runtime.

This guide covers, in order:

1. [Setup](#setup): the steps every app needs, and the optional ones.
2. [Light and dark](#light-and-dark): following the OS, a user toggle, and no
   flash on load.
3. [Brand themes](#brand-themes-createtheme): `createTheme` and `ThemeProvider`.
4. [Overriding in plain CSS](#overriding-in-plain-css), for one-off changes.
5. [Per-component variables](#per-component-variables).
6. [Server rendering and frameworks](#server-rendering-and-frameworks).
7. [Adding tokens](#adding-your-own-tokens), [custom breakpoints](#custom-breakpoints) and [without React](#without-react).
8. [Token reference](#token-reference) and [troubleshooting](#troubleshooting).

## How it fits together

| Layer               | What it holds                        | Set by                                   |
| ------------------- | ------------------------------------ | ---------------------------------------- |
| `greese.tokens`     | Default token values, light and dark | `styles.css`                             |
| `greese.theme`      | Your themes' token values            | `createTheme` + `ThemeProvider`          |
| `greese.components` | Component styles, which read tokens  | `styles.css` or `css/<Name>.css`         |
| `greese.overrides`  | Your component overrides             | The SCSS kit (Guides/Styling components) |
| `greese.utilities`  | Style props and the `greese` prop    | Props, per instance                      |
| (unlayered)         | Your own CSS                         | You                                      |

All library CSS lives in [cascade layers](https://developer.mozilla.org/docs/Web/CSS/@layer).
Unlayered CSS always beats layered CSS whatever the specificity, so your
stylesheet wins without `!important`.

Two attributes drive everything, and they work on any element, `<html>`
included:

- `data-greese-scheme="light" | "dark" | "system"` forces a color scheme for
  that subtree. With no attribute anywhere, the page follows the OS.
- `data-greese-theme="<name>"` applies a theme from `createTheme`.

## Setup

No provider is needed to use greese ui: the styles load once and every component works. `ThemeProvider` is optional. Reach for it only to apply a `createTheme()` theme, or to force a color scheme, on all or part of the page. The steps below say which are required.

### 1. Install (required)

```sh
npm install @greese/react
```

`@greese/ui` comes with it. React 19 is a peer dependency.

### 2. Load the styles (required)

Pick **one** of these:

```ts
// Everything (about 23 kB brotli). Simplest.
import '@greese/react/styles.css'
```

```ts
// Only what you use: each file @imports the tokens and the components it
// builds on, and bundlers de-duplicate shared imports.
import '@greese/react/css/Button.css'
import '@greese/react/css/Dialog.css'
```

Optionally, also load the reset and page defaults (box-sizing, body font and
colors, `canvas` background):

```ts
import '@greese/react/base.css'
```

Without `base.css`, components are still fully styled. Your page background
just won't switch with the color scheme unless you set it yourself, for
example with `body { background: var(--greese-color-canvas); color: var(--greese-color-fg) }`.

At this point everything follows the OS light/dark setting. **No provider is
required.** The remaining steps are optional.

### 3. Stop the dark-mode flash (recommended if users can choose a scheme)

If you let users pick a scheme, their saved choice must apply before the
first paint. Put this inline script in `<head>`, before your stylesheets:

```tsx
import { getSchemeScript } from '@greese/react'

;<head>
  <script dangerouslySetInnerHTML={{ __html: getSchemeScript() }} />
</head>
```

It reads `localStorage` and sets `data-greese-scheme` on `<html>`. It's a few
hundred bytes, and it never throws, even when storage is blocked. If your CSP
blocks inline scripts, add a nonce or hash for it.

Because the script changes `<html>` before React hydrates, add
`suppressHydrationWarning` to your `<html>` element in server-rendered apps.

### 4. Add a scheme toggle (optional)

```tsx
'use client'
import {
  SegmentedControl,
  Segment,
  useColorScheme,
  type ColorScheme,
} from '@greese/react'

export function SchemeToggle() {
  const { scheme, setScheme } = useColorScheme()
  return (
    <SegmentedControl
      label="Theme"
      value={scheme}
      onValueChange={(value) => setScheme(value as ColorScheme)}
    >
      <Segment value="system">System</Segment>
      <Segment value="light">Light</Segment>
      <Segment value="dark">Dark</Segment>
    </SegmentedControl>
  )
}
```

`setScheme` writes one attribute and saves the choice. `resolvedScheme` tells
you what's actually showing (`system` resolved against the OS). If you pass a
custom `storageKey` to `useColorScheme`, pass the same one to
`getSchemeScript`.

### 5. Add a brand theme (optional)

See [Brand themes](#brand-themes-createtheme). To theme the whole app, wrap
the root:

```tsx
<ThemeProvider theme={brand} asChild>
  <body>…</body>
</ThemeProvider>
```

## Light and dark

Every color token has a light and a dark value. Which one applies is decided
per element:

| Situation                                                         | Result                                  |
| ----------------------------------------------------------------- | --------------------------------------- |
| No `data-greese-scheme` anywhere                                  | Follows the OS (`prefers-color-scheme`) |
| `data-greese-scheme="dark"` on `<html>` (set by `useColorScheme`) | Whole page dark                         |
| `<ThemeProvider scheme="dark">` around a section                  | That section dark, whatever the page is |
| `scheme="system"` on a provider inside a forced-dark page         | That section follows the OS again       |

Schemes nest, so a light card inside a dark hero is just a nested provider:

```tsx
<ThemeProvider scheme="dark">
  <Hero>
    <ThemeProvider scheme="light">
      <Card>…</Card>
    </ThemeProvider>
  </Hero>
</ThemeProvider>
```

The scheme also sets CSS `color-scheme`, so native scrollbars, form controls
and date pickers match.

## Brand themes: `createTheme`

```tsx
import { createTheme, ThemeProvider } from '@greese/react'
import { palette } from '@greese/ui'

// At module scope: it builds a static CSS string once.
export const brand = createTheme({
  name: 'brand',
  color: {
    // A light/dark pair, from the palette (Foundations/Color)…
    primary: { light: palette.lavender[600], dark: palette.lavender[300] },
    // primaryContent and primaryStrong follow: readable ink (WCAG AA) and a
    // hover shade, derived for you. Set them to choose your own, in any CSS
    // color, one value or a pair.
    secondary: '#0f766e',
  },
  radius: { sm: '6px', md: '12px', lg: '20px' },
  font: { body: "'Inter', system-ui, sans-serif" },
})

<ThemeProvider theme={brand}>…</ThemeProvider>
```

What to know:

- **Any token can be overridden.** Colors take a string or a
  `{ light, dark }` pair. Every other group (`space`, `radius`, `font`,
  `fontWeight`, `lineHeight`, `shadow`, `zIndex`, `duration`,
  `easing`) takes strings. Values can be any CSS: `oklch(…)`, `var(--x)`,
  `clamp(…)`. Characters that could break out of a declaration (`;`, `{`,
  `}`, `<`, `>`) throw.
- **Themes replace, they don't stack.** A theme is the defaults plus its
  overrides, and it declares every token. Nesting `ThemeProvider theme={a}`
  inside `theme={b}` gives you exactly `a`. To extend a theme, spread your
  options: `createTheme({ ...brandOptions, name: 'brand-compact', space: { … } })`.
- **Theme and scheme are independent.** A scheme-only provider inside a theme
  keeps the theme, and vice versa.
- **Four brand colors, in order: `primary`, `secondary`, `tertiary`,
  `accent`.** Components use `primary` for interactive emphasis (solid
  buttons, links, focus, selection), and every `tone` prop takes all four.
  Set `primary` to rebrand; the focus ring follows it.
- **Derived states follow.** Hover, active, soft and outline variants are
  computed from the tone with `color-mix()`. Change `primary`, and every
  button, link, focus ring and selected state updates, in both schemes.
- **Content colors are derived and WCAG-safe.** Each brand color (and
  `negative`) has a `…Content` color for text and icons on it
  (`--greese-color-primary-content`). When you set the main color,
  `createTheme` picks the more readable of white and near-black, at least
  4.5:1, separately for light and dark, and mixes a `…Strong` shade from it.
  Anything you set yourself wins. Colors it can't measure (`var()`,
  `oklch()`) keep the default content color, so check those. The SCSS kit's
  `tokens()` does the same at build time.
- **No cost per render.** `ThemeProvider` renders a `<style href precedence>`
  that React 19 hoists into `<head>` and de-duplicates, plus two attributes.
  The wrapper is `display: contents`; use `asChild` to put the attributes on
  your own element instead.
- `name` scopes the CSS (`[data-greese-theme="brand"]`). Use letters, digits
  and `-`, and give each theme a unique name.

Read the nearest provider's theme and scheme with `useThemeScope()`, for
example to pick a matching chart palette.

**At build time instead.** The SCSS kit compiles the same theme into your
CSS, with no theme object in JavaScript, and **Theme Studio** builds one
visually. Pass the name to the provider; it stamps the attributes and
injects nothing:

```scss
@use 'pkg:@greese/ui/scss/kit' as greese;

@include greese.theme(brand) {
  @include greese.tokens(
    (
      color: (
        primary: (
          light: #7c3aed,
          dark: #c4b5fd,
        ),
      ),
    )
  );
}
```

```tsx
<ThemeProvider theme="brand">…</ThemeProvider>
```

See **Guides/Styling components**.

### Several themes on one page

```tsx
const ocean = createTheme({ name: 'ocean', color: { primary: '#0891b2' } })
const sunset = createTheme({ name: 'sunset', color: { primary: '#ea580c' } })

<ThemeProvider theme={ocean}><Pricing plan="pro" /></ThemeProvider>
<ThemeProvider theme={sunset}><Pricing plan="team" /></ThemeProvider>
```

Each theme's CSS is injected once, however many providers use it.

## Shapes

A shape outlines an element with one clip and a border that follows it, and
animates by its parameters. A 12px corner stays 12px at any size, and the
border never comes apart from the shape, mid-animation included.

### Shape and motion themes

A theme composes three layers: colors, shapes and motion (ADR 0025). Each
layer's themes change only that layer, so they mix freely.

**Themes reassign; they never overwrite.** A color theme points the color roles
(`primary`, `surface`…) at colors, a shape theme points the radius roles at the
radius scale, and a motion theme points the motion roles at effects and timing
tokens. The palette, the radius scale, the duration and easing tokens and every
effect keep their own values under every theme: `--greese-radius-md` is 8px and
`fadeUp` fades up, whatever the page wears.

**Shape themes** reassign the radius roles and outline every kind of component
(controls, fields, containers, indicators, avatars, tabs), with smaller
features on smaller controls. They set no colors and no motion.

| Theme     | Shapes                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------- |
| `bevel`   | Chamfered corners that slide to the other diagonal on hover; hexagon indicators, trapezoid tabs         |
| `ticket`  | Round side notches on containers, fields and tabs; tag-shaped controls and badges                       |
| `ridge`   | Zigzag hems on containers, zigzag ends on controls, zigzag-topped tabs, diamond knobs                   |
| `folio`   | Dog-eared containers, leaning controls; tab panels are folders the current tab opens into               |
| `soft`    | Every corner rounded, a step rounder than the library; accordion items as rounded panels                |
| `pebble`  | Controls, fields, tabs and badges as pills, so square ones are circles; containers extra-rounded        |
| `extrude` | Keycap depth drawn inside each box: raised controls that sink when pressed, recessed fields             |
| `tilt`    | Real perspective on hover and press: controls lean back, cards turn and lift, the current tab stands up |

The first four outline components with a clip and a ring (ADR 0024). Soft and
Pebble only reassign radius roles; Extrude and Tilt add depth, Extrude with
inset shadows (inside the box, so a motion theme's mask never cuts them off)
and Tilt with `transform` on hover and press only, so nothing rests turned
and a motion theme's three-dimensional entrances start and end where the
element sits.

**Motion themes** pace every entrance and assign which built-in effect plays
where: the `'theme'` entrance (`greese="theme"`, so a page's reveals follow the
theme), tab panels and an accordion's content, table rows, toasts and overlays,
each with the duration and easing it takes. They set no colors and no shapes.

| Theme    | Motion                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| `snappy` | Short and sharp: reveals pop in, overlays scale in and away                                                   |
| `gentle` | Long and soft: content comes into focus out of a blur, overlays sink away                                     |
| `wipe`   | Revealed, not moved: reveals wipe up, menus wipe down, dialogs open and close as a circle                     |
| `pocket` | Everything rises out of an invisible slot at one of its own edges, and sinks back in                          |
| `depth`  | In three dimensions: reveals flip up, menus swing down from their top edge, dialogs rise from behind the page |

**Color variants** say how a color theme's colors are worn, so any color
theme takes any variant. `outline` draws what is usually filled (solid and
soft buttons and badges, soft alerts, filled and elevated cards and tiles,
avatars, the current tab and segment, toasts, tooltips) as an outline in its color, with text to match,
and fills what was outlined. A variant reassigns the colors each component
variant draws with (`modifiers` in the kit), never the color tokens or
component SCSS, so it goes with every shape theme.

```ts
import '@greese/ui/themes/outline.css'
```

Load one of each after greese ui's styles:

```ts
import '@greese/react/styles.css'
import '@greese/ui/themes/bevel.css'
import '@greese/ui/themes/wipe.css'
```

Wipes, irises and pockets are masks, so they compose with a shape's clip; no
effect touches `clip-path`. Every motion theme's entrances are off for visitors
who reduce motion.

#### Motion roles

Components have no motion of their own: each says what it is (a dialog, a
popover) and where it opens from (`--greese-overlay-origin`), and reads its
motion from a role. Assign roles with the kit's `motion-defaults()`; effects by
name, durations and easings by token name or as values:

```scss
@include greese.motion-defaults(
  (
    theme: pocket-up,
    // greese="theme"
    content: wipe-open-x,
    // tab panels', an opening accordion's children
    rows: fade-up,
    // a table's rows, one after another
    dialog: iris-in,
    dialog-exit: iris-out,
    popover: wipe-down,
    // menus and speed-dial actions too
    popover-exit: wipe-out-up,
    content-duration: slow,
    // var(--greese-duration-slow)
    enter-ease: enter,
    // var(--greese-easing-enter)
  )
);
```

| Role                                                                                                            | Plays                                           | Base theme                                           |
| --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------- |
| `theme`                                                                                                         | `greese="theme"`                                | `fadeUp`                                             |
| `content`                                                                                                       | tab panels' and an opening accordion's children | a short rise                                         |
| `rows`                                                                                                          | table rows                                      | none                                                 |
| `toast`, `backdrop`                                                                                             | toasts, a dialog's scrim                        | a short rise, a fade                                 |
| `overlay`                                                                                                       | every overlay but a drawer                      | a fade from its origin                               |
| `dialog`, `popover`, `tooltip`                                                                                  | one kind (falls back to `overlay`)              | `overlay`'s                                          |
| `drawer`                                                                                                        | drawers and the off-canvas sidebar              | a slide from its edge                                |
| `overlay-exit`, `dialog-exit`, `popover-exit`, `tooltip-exit`, `drawer-exit`                                    | how they leave                                  | a fade toward the origin                             |
| `content-duration`, `rows-duration`, `overlay-duration`, `toast-duration`, `backdrop-duration`, `exit-duration` | how long                                        | `normal`, `slow`, `fast`, `normal`, `normal`, `fast` |
| `enter-ease`, `exit-ease`                                                                                       | the curves                                      | `enter`, `exit`                                      |

Each is a custom property, `--greese-motion-<role>` (an exit role's are
`--greese-motion-<role>-<property>`), so plain CSS can assign one too. A
component's `motion()` in the kit, or an instance's `greese` prop, overrides
its role.

#### Radius roles

Components read the radius roles, never the radius scale directly:

| Role                      | Parts                                                     | Base theme |
| ------------------------- | --------------------------------------------------------- | ---------- |
| `--greese-corner-control` | buttons, segmented controls, file pickers                 | `md`       |
| `--greese-corner-field`   | text fields and selects, OTP cells                        | `md`       |
| `--greese-corner-surface` | cards, dialogs, fieldsets, lists, stats, chat bubbles     | `lg`       |
| `--greese-corner-panel`   | alerts, tiles, tables, code, media, popovers and menus    | `md`       |
| `--greese-corner-inset`   | tabs, menu items, tooltips, keys, checkboxes              | `sm`       |
| `--greese-corner-pill`    | badges, chips, tracks, progress bars                      | `pill`     |
| `--greese-corner-round`   | knobs, thumbs, radios, step markers, avatars, status dots | `round`    |

A shape theme points them at `none` (`createTheme({ corner: { control:
'var(--greese-radius-none)' } })`, or `tokens.corner` in the kit), and Bevel and
Ridge also turn round parts to diamonds. Your own CSS can use a role to follow
the theme, or the scale to stay as it is.

### Any element

Every shape is also a class. A shape theme's `bevel-card`, for example:

```html
<section class="greese-shape-bevel-card">…</section>
```

Its parameters are custom properties, so one element can differ:
`style="--greese-shape-a: 32px"`. So is its border color:
`--greese-shape-ring`.

### Making your own

In Theme Studio's **Shapes** tab:

- start from a preset (bevel, notch, tag, hexagon, slant, dog-ear, ticket,
  zigzag, shield);
- drag its points;
- set its parameters for rest, hover, pressed and entrance;
- choose which components take it.

The theme's SCSS and CSS include it. From code, `shapesCss()` in
`@greese/ui/shapes` writes the same CSS (a build-time module, not a runtime
one).

Every shape:

- keeps keyboard focus visible: it opens to its box for the focus ring, or
  draws a ring inside;
- moves only for visitors who allow motion;
- keeps shaped buttons 44px on touch screens;
- steps aside in forced-colors mode.

A clip also cuts anything painted outside the box, so shaped elements don't
cast shadows. ADR 0024 has the details.

## Overriding in plain CSS

For a quick change, set tokens in your own (unlayered) stylesheet.
Scheme-independent tokens are simple:

```css
:root {
  --greese-radius-md: 12px;
  --greese-font-body: 'Inter', system-ui, sans-serif;
}
```

**Colors need care.** The default dark values are declared on
`[data-greese-scheme]` elements and under `prefers-color-scheme: dark`. A plain
`:root { --greese-color-primary: … }` would therefore apply in dark mode too,
and be ignored inside any `<ThemeProvider scheme>`. Mirror the library's
selectors:

```css
:root,
[data-greese-scheme='light'],
[data-greese-scheme='system'] {
  --greese-color-primary: #7c3aed;
}

@media (prefers-color-scheme: dark) {
  :root:not([data-greese-scheme='light']),
  [data-greese-scheme='system'] {
    --greese-color-primary: #c4b5fd;
  }
}

[data-greese-scheme='dark'] {
  --greese-color-primary: #c4b5fd;
}
```

`createTheme` generates exactly this for you, so prefer it for colors.

Also note that a `ThemeProvider` theme declares every token on its own
element, so `:root` overrides don't reach inside one. Put the override in the
theme instead.

## Per-component variables

Some components expose variables for things a token can't express. Set them
on the component, a class, or any ancestor:

```css
/* Every button in this area uses the negative tone. */
.danger-zone .greese-Button {
  --greese-button-tone: var(--greese-color-negative);
  --greese-button-on-tone: var(--greese-color-on-negative);
}

/* A wider sidebar and roomier cards. */
.app {
  --greese-sidebar-width: 18rem;
}
.greese-Card {
  --greese-card-padding: var(--greese-space-6);
}
```

| Component                             | Variables                                                                                                                                                                                                                                |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Button, IconButton                    | `--greese-button-tone`, `--greese-button-on-tone` (variants derive from these), `--greese-button-height`, `--greese-button-padding`                                                                                                      |
| Input, Select, Textarea, FileInput    | `--greese-input-height`, `--greese-input-padding`, `--greese-select-height`, `--greese-select-padding`, `--greese-textarea-padding`, `--greese-file-height`, `--greese-file-padding`                                                     |
| Card                                  | `--greese-card-padding`                                                                                                                                                                                                                  |
| Dialog                                | `--greese-dialog-width`                                                                                                                                                                                                                  |
| Sidebar                               | `--greese-sidebar-width`                                                                                                                                                                                                                 |
| Avatar, Spinner, Progress             | `--greese-avatar-size`, `--greese-spinner-size`, `--greese-progress-height`                                                                                                                                                              |
| Slider, ColorPicker                   | `--greese-slider-thumb`, `--greese-colorpicker-thumb`                                                                                                                                                                                    |
| SegmentedControl, Table               | `--greese-segment-height`, `--greese-table-cell-padding`                                                                                                                                                                                 |
| Rating, Status, Stat, List            | `--greese-rating-size`, `--greese-rating-on`, `--greese-rating-off`, `--greese-status-size`, `--greese-stat-padding`, `--greese-list-padding`                                                                                            |
| ScrollCarousel, Diff, Steps, RadialProgress | `--greese-scrollcarousel-gap`, `--greese-diff-thumb`, `--greese-steps-marker`, `--greese-steps-prefix` (the before-column), `--greese-chat-tail`, `--greese-tile-padding`, `--greese-radialprogress-size`, `--greese-radialprogress-thickness` |
| Motion (the `greese` prop)            | `--greese-motion-duration`, `--greese-motion-delay`, `--greese-motion-distance`, `--greese-motion-ease`, and the named curves `--greese-ease-in`, `-out`, `-in-out`. Set on `:root` or any ancestor (see **Guides/Animation**)           |

This table is the short list. Every component's docs page ends with a
**Styling** section listing all its classes and variables, and
**Guides/Styling components** covers overriding them, the SCSS kit,
theme-wide motion and Theme Studio.

Class names (`greese-Button`, `greese-Card`, …) are stable, prefixed and never
hashed, so they're safe to target. Internal parts (`greese-Dialog-title`) may
change in a minor release; through the SCSS kit, a renamed part fails your
build instead of silently not matching.

## Server rendering and frameworks

Theming is plain CSS plus attributes, so it renders on the server with no
extra setup. Two things to get right:

- Put `getSchemeScript()` in `<head>` and add `suppressHydrationWarning` to
  `<html>` (see [step 3](#3-stop-the-dark-mode-flash-recommended-if-users-can-choose-a-scheme)).
- Call `createTheme` at module scope, never during render.

**Next.js (App Router)**, `app/layout.tsx`:

```tsx
import { getSchemeScript, ThemeProvider } from '@greese/react'
import '@greese/react/base.css'
import '@greese/react/styles.css'
import { brand } from './theme'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <script dangerouslySetInnerHTML={{ __html: getSchemeScript() }} />
      </head>
      <ThemeProvider theme={brand} asChild>
        <body>{children}</body>
      </ThemeProvider>
    </html>
  )
}
```

`ThemeProvider` is a client component; a server-component layout can render
it as shown. A component that calls `useColorScheme` needs `'use client'`.

**Vite / single-page apps**: put the script tag in `index.html`, inline:

```html
<script>
  /* paste the output of getSchemeScript() here, or inject it at build time */
</script>
```

## Typography

The type system, named text styles that change across breakpoints, is set in
a theme with `typography` (see Foundations/Typography):

```ts
createTheme({
  name: 'brand',
  typography: { h1: { base: { size: '2rem' }, lg: { size: '4rem' } } },
})
```

## Adding your own tokens

`createTheme` takes `extend` for tokens the system doesn't have. Each is
declared as `--greese-<group>-<name>` in that theme (a color in both schemes),
for your CSS and component overrides to read:

```ts
export const brand = createTheme({
  name: 'brand',
  extend: {
    color: { 'brand-ink': { light: '#1b1340', dark: '#e5defc' } },
    lineHeight: { loose: '2' },
    space: { 9: '4rem' },
  },
})
```

An existing name, or a group that doesn't exist, throws; set built-in tokens
through their own group. The SCSS kit has the same option (`$extend`: see
Guides/Styling components), and Theme Studio adds them with the "Add a
… token" row in each token section.

## Custom breakpoints

Breakpoint values compile into media queries, so they're fixed when the
stylesheet is built, not in a theme and not at runtime. You can change the
values and **add keys**. The five built-in keys (`xs`–`xl`) stay, because
components use them; list the keys smallest first, with `xs` at `0px`, and
write each as one word (quote one that starts with a digit: `'2xl'`):

```scss
// your-styles.scss, instead of importing styles.css
@use 'pkg:@greese/ui/scss' with (
  $breakpoints: (
    xs: 0px,
    sm: 480px,
    tablet: 700px,
    md: 768px,
    lg: 1024px,
    xl: 1440px,
  )
);
```

Every key, added ones included, gets responsive classes
(`greese-Stack--tablet-gap-3`, so `gap={{ tablet: 3 }}` works) and a custom
property in the built CSS, **`--greese-breakpoint-tablet: 700px`**, which
your own CSS and JavaScript can read, for example
`max-inline-size: var(--greese-breakpoint-md)`. (A custom property can't go
inside a `@media` condition; that's why the values are fixed at build time.)

```ts
// Before the first render: hooks and Sidebar read these in JS.
import { configureBreakpoints } from '@greese/react'
configureBreakpoints({ sm: 480, tablet: 700, md: 768, lg: 1024, xl: 1440 })

// For TypeScript, tell it about an added key (once, in any .d.ts):
declare module '@greese/ui' {
  interface BreakpointKeys {
    tablet: true
  }
}
```

Compile with Sass's `NodePackageImporter`, which resolves `pkg:` URLs. In Vite:

```ts
import { NodePackageImporter } from 'sass-embedded'

export default defineConfig({
  css: { preprocessorOptions: { scss: { importers: [new NodePackageImporter()] } } },
})
```

## Without React

A theme is just a string. Serve `brand.css` yourself (write it at build time,
or inline it from the server) and set the attribute:

```ts
import { writeFileSync } from 'node:fs'
import { brand } from './theme'

writeFileSync('public/brand.css', brand.css)
```

```html
<link rel="stylesheet" href="/brand.css" />
<html data-greese-theme="brand">
  …
</html>
```

`@greese/ui/tokens.css` has the default tokens on their own, for
non-React code that should match.

## Token reference

The live values, with swatches, are under **Foundations/Tokens**, and the
color roles and palette under **Foundations/Color**. The property name is
`--greese-<group>-<key>`, with camelCase keys in kebab case.

| Group        | `createTheme` key    | Keys                                                                                                                                                                                                                                                             |
| ------------ | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Color        | `color`              | `canvas`, `surface`, `surfaceOverlay`, `fg`, `fgMuted`, `border`, `borderStrong`, `track`, `primary`, `secondary`, `tertiary`, `accent` (each with `…Strong` and `…Content`), `focusRing`, `positive`, `negative`, `negativeContent`, `warning`, `info`, `scrim` |
| Spacing      | `space`              | `0`–`8` (`0`, `0.25rem`, `0.5rem`, `0.75rem`, `1rem`, `1.5rem`, `2rem`, `3rem`, `4rem`)                                                                                                                                                                          |
| Radius       | `radius`             | `none`, `sm`, `md`, `lg`, `xl`, `pill`, `round`                                                                                                                                                                                                                  |
| Radius roles | `corner`             | `control`, `field`, `surface`, `panel`, `inset`, `pill`, `round`: which step of `radius` each kind of part takes                                                                                                                                                 |
| Font family  | `font`               | `body`, `mono`                                                                                                                                                                                                                                                   |
| Type system  | `typography`         | variants `p1`–`p3`, `h1`–`h6`, `s1`, `s2`, `caption`, `button`: font size, weight, letter spacing, line height (see Typography)                                                                                                                                  |
| Font weight  | `fontWeight`         | `regular`, `medium`, `semibold`, `bold`                                                                                                                                                                                                                          |
| Line height  | `lineHeight`         | `tight`, `snug`, `normal`                                                                                                                                                                                                                                        |
| Shadow       | `shadow`             | `sm`, `md`, `lg`                                                                                                                                                                                                                                                 |
| Stacking     | `zIndex`             | `dropdown`, `sticky`, `overlay`, `modal`, `popover`, `toast`, `tooltip`                                                                                                                                                                                          |
| Motion       | `duration`, `easing` | `fast`, `normal`, `slow`; `standard`, `enter`, `exit`                                                                                                                                                                                                            |

Durations collapse to near zero under `prefers-reduced-motion: reduce`, in
themes too.

## Troubleshooting

| Symptom                                                                  | Cause and fix                                                                             |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Dark-mode users see a white flash on load                                | Add `getSchemeScript()` to `<head>`, before stylesheets                                   |
| Hydration warning about `data-greese-scheme`                             | Add `suppressHydrationWarning` to `<html>`                                                |
| My `:root` color override is ignored in dark mode or in a scheme section | Use `createTheme`, or mirror the scheme selectors ([plain CSS](#overriding-in-plain-css)) |
| My `:root` override is ignored inside a `ThemeProvider`                  | Themes declare every token; put the override in the theme                                 |
| A nested theme lost the outer theme's overrides                          | Themes replace, not stack; spread the outer theme's options into the inner one            |
| The page background doesn't change with the scheme                       | Import `base.css`, or set `background: var(--greese-color-canvas)` yourself               |
| The saved choice isn't restored                                          | `useColorScheme` and `getSchemeScript` must use the same `storageKey`                     |
| Breakpoint changes have no effect on components                          | Recompile the SCSS with `$breakpoints`; `configureBreakpoints` only affects JS            |
