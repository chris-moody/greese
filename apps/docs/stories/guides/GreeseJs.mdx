# greese.js

greese.js (`@greese/js`) is a small keyframe and timeline animation
library for the web. It's about 5.9 kB brotli (6.8 kB with every extra), has no
dependencies and needs no framework. Timelines play, pause, seek, reverse,
scale time, repeat, yoyo and nest. It animates:

- CSS properties and individual transforms;
- custom properties;
- text;
- SVG attributes;
- plain objects.

This page covers greese.js **on its own, without greese ui**. For motion in
greese ui components (the `greese` prop), see **Guides/Animation**. Every
function, option and type, with examples, is in the
[greese.js API reference](?path=/docs/guides-greese-js-api--docs). Live demos
are under **Motion/greese.js**.

### npm and a bundler

```sh
npm install @greese/js
```

```ts
import { animate, timeline, splitText, ease } from '@greese/js'

animate('.card', { opacity: [0, 1], y: [16, 0] }, { duration: 0.4, stagger: 0.05 })
```

- It's ESM only, with `sideEffects: false`, so bundlers tree-shake what you
  don't import: `ease` alone is under 1 kB.
- Types are included; there's no `@types` package.

### Inside greese ui

`@greese/react` depends on greese.js and re-exports `animate`,
`timeline`, `Timeline`, `ease`, `cubicBezier`, `splitText` and their types:

```ts
import { animate, timeline } from '@greese/react'
```

greese ui also adds the `greese` prop and the `useGreese()` hook; see
**Guides/Animation**.

### CDN, as an ES module

No install and no build: import straight from a CDN in a module script. Pin
the version.

```html
<script type="module">
  import { animate } from 'https://cdn.jsdelivr.net/npm/@greese/js@0.1/+esm'
  // or: 'https://unpkg.com/@greese/js@0.1/dist/index.js'

  animate('h1', { opacity: [0, 1], y: [20, 0] }, { duration: 0.6 })
</script>
```

### A classic script tag

`dist/greese.global.js` is a single minified file (about 7 kB brotli) that
defines `window.greese`. It's the package's default file on unpkg and
jsDelivr.

```html
<script src="https://unpkg.com/@greese/js@0.1/dist/greese.global.js"></script>
<script>
  const { timeline } = window.greese
  timeline({ repeat: -1, yoyo: true }).to('.logo', { rotate: 10, duration: 0.8 })
</script>
```

With a bundler, the same file is available as `@greese/js/global`.

### Node and servers

Importing greese.js never touches the DOM, so it's safe in server-rendered
code and Server Components. On a server there's no animation frame, so
timelines don't play by themselves; drive them with `seek()` or `progress()`.
That's useful for tests, or for rendering frames (canvas, video) offline:

```ts
import { timeline } from '@greese/js'

const state = { x: 0, opacity: 0 }
const tl = timeline({ paused: true })
  .to(state, { x: 300, duration: 1, ease: 'out' })
  .to(state, { opacity: 1, duration: 0.5 }, '<')

for (let frame = 0; frame <= 30; frame++) {
  tl.seek(frame / 30)
  drawFrame(state) // your renderer
}
```

## In frameworks (without greese ui)

The rules are the same everywhere:

- build a timeline once the elements exist;
- `kill()` it when they go away, which also restores what it animated.

### React

```tsx
import { useEffect, useRef } from 'react'
import { timeline } from '@greese/js'

export function Hero() {
  const root = useRef<HTMLDivElement>(null)
  useEffect(() => {
    // Selector strings match inside `scope`: this component's elements only.
    const tl = timeline({ scope: root.current! })
      .from('h1', { opacity: 0, y: 24 })
      .from('li', { opacity: 0, x: -12, stagger: 0.05 }, '-=0.2')
    return () => {
      tl.kill()
    }
  }, [])
  return <div ref={root}>…</div>
}
```

Don't return a timeline from an effect, or from anything React treats as a
promise: a timeline is awaitable.

### Vue

```vue
<script setup lang="ts">
import { onBeforeUnmount, onMounted, ref } from 'vue'
import { timeline, type Timeline } from '@greese/js'

const card = ref<HTMLElement>()
let tl: Timeline | undefined
onMounted(() => {
  tl = timeline().from(card.value!, { opacity: 0, scale: 0.95, duration: 0.4 })
})
onBeforeUnmount(() => tl?.kill())
</script>

<template><div ref="card">…</div></template>
```

### Svelte

```svelte
<script lang="ts">
  import { animate } from '@greese/js'
  // An action: runs when the element mounts, cleans up when it unmounts.
  const reveal = (node: HTMLElement) => {
    const tl = animate(node, { opacity: [0, 1], y: [16, 0] }, { duration: 0.5 })
    return { destroy: () => tl.kill() }
  }
</script>

<section use:reveal>…</section>
```

### Plain JavaScript

```ts
import { animate, splitText } from '@greese/js'

const { elements } = splitText(document.getElementById('title')!)
const intro = animate(elements, { opacity: [0, 1], y: [10, 0] }, { stagger: 0.03 })
document.getElementById('replay')!.addEventListener('click', () => intro.restart())
```

## The one-call API

```ts
animate('.card', { opacity: [0, 1], y: [16, 0] }, { duration: 0.4, stagger: 0.05 })
```

`animate(targets, keyframes, options)` builds a timeline, plays it on the
next frame and returns it.

- **Targets**: a selector, an element, a list of elements (NodeList, array),
  or any object.
- **Times are seconds** (WAAPI uses milliseconds).
- **`delay`** waits before starting: `{ delay: 0.3 }`. On a timeline a
  position says this and more, so `delay` is for this one-call form.
- **Keyframes** come in two forms, as with `element.animate()`:
  - **Property lists**: `{ opacity: [0, 1], x: [0, 40, 20] }`. Values are
    spaced evenly; a single value animates from the current one.
  - **Frames**: `[{ scale: 1 }, { scale: 1.2, offset: 0.3, ease: 'in' }, { scale: 1 }]`.
    `offset` (0–1) places a frame (missing offsets are spaced evenly), and a
    frame's `ease` applies until the next frame.
- **Per-target values**: any value can be a function of the target's index,
  the target and the list, worked out once as the animation is built, so one
  call gives each target its own: `{ y: (i) => -8 - i * 4 }`. In the
  property-list form a function goes in the list:
  `{ y: [0, (i) => -8 - i * 4] }`.
- **Stagger** is seconds between neighbours, `{ each, from }` (`from`:
  `'start'`, `'end'`, `'center'` or an index), or a function giving each
  target its own offset, such as one ordered by position:
  `stagger: (i, el) => el.getBoundingClientRect().left / 1000`.

## Timelines

```ts
const intro = timeline()
  .to('.title', { opacity: 1, y: 0, duration: 0.6 })
  .from('.card', { opacity: 0, y: 24, stagger: 0.08 }, '-=0.3')
  .call(() => track('intro-done'))
```

| Method                                              | Does                                                                           |
| --------------------------------------------------- | ------------------------------------------------------------------------------ |
| `.to(targets, vars, position?)`                     | Animates from current values to `vars`                                         |
| `.from(targets, vars, position?)`                   | From `vars` to current values; `vars` show until it starts, so nothing flashes |
| `.fromTo(targets, from, to, position?)`             | Both ends explicit                                                             |
| `.animate(targets, keyframes, options?, position?)` | Keyframes, as above                                                            |
| `.set(targets, vars, position?)`                    | Sets values at a point in time                                                 |
| `.add(timeline \| fn, position?)`                   | Nests a timeline, or schedules a callback                                      |
| `.call(fn, position?)`                              | Runs `fn` when the playhead passes, in either direction                        |
| `.label(name, position?)`                           | Names a time                                                                   |

`vars` holds property values plus `duration` (default `0.5`), `ease` (default
`'out'`) and `stagger`.

**Positions** place each child:

| Position                   | Means                                                |
| -------------------------- | ---------------------------------------------------- |
| omitted                    | At the end: calls run in sequence                    |
| `1.5`                      | At 1.5 s                                             |
| `'+=0.2'` / `'-=0.2'`      | 0.2 s after / before the current end                 |
| `'<'` / `'<0.1'`           | With / 0.1 s after the previous child's start        |
| `'>'` / `'>-0.2'`          | At / 0.2 s before the previous child's end           |
| `'intro'` / `'intro+=0.5'` | At / after a label (labels can't contain `+` or `-`) |

### Controls

`play(from?)`, `pause()`, `resume()`, `reverse(from?)`, `restart()`,
`seek(timeOrLabel)`, `progress(0–1)`, `time(s)`, `timeScale(n)`,
`duration()`, `totalDuration()`, `isActive()`, `invalidate()`, and `kill()`,
which stops and restores every animated property.

`killTweensOf(targets)` stops one target and leaves the timeline's others
running. There is a free function of the same name for when you don't hold the
timeline — see below.

Options: `paused`, `repeat` (`-1` is forever), `yoyo`, `repeatDelay`,
`timeScale`, `reducedMotion`, `scope` (selector strings match inside that element), `fps` (whole frames only), `ticker` (`false` for your own clock), `onUpdate`, `onComplete`.

A timeline is awaitable: `await animate(el, …)` resolves when it completes. It
resolves with no value, so returning a timeline from an `async` function or a
`then` callback waits for it to finish. That's usually what you want, but
don't return a _paused_ timeline from one.

### Nesting

```ts
const spin = timeline({ repeat: 2 }).to(icon, { rotate: 360, ease: 'linear' })
const page = timeline().add(spin).add(slideIn.timeScale(2), '<0.3')
page.reverse() // plays everything backwards, nested timelines included
```

A nested timeline stops running its own clock and is driven by its parent,
through its own `repeat`, `yoyo` and `timeScale`.

## Taking a target back: `killTweensOf`

```ts
import { killTweensOf } from '@greese/js'

killTweensOf(particle) // whatever is animating it, wherever it started
killTweensOf('.card') // every element matching
```

Stops every animation on those targets and puts their properties back. The
targets' neighbours in the same timelines keep running, and it returns how many
timelines it stopped animating.

Reach for it where something else is about to take a property over, so two
animations don't fight: a new hit reaction on a sprite that's already
recoiling, a particle going back to its pool mid-tween, an element animated
again from another module.

It's the counterpart to `kill()`. That stops a timeline you hold a reference
to; this stops whatever is animating a target you hold a reference to — which
is the case that comes up in a game loop, where the code reacting to a hit has
the sprite but not the tween. A timeline has the method too
(`tl.killTweensOf(o)`), scoped to itself and its children, for when you do hold
it and mean "this one only".

## What can be animated

| Property                                             | Notes                                                                                                                                                                     |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x`, `y`, `z`, `rotate`, `scale`, `scaleX`, `scaleY` | Written to the individual `translate`, `rotate` and `scale` properties: they compose without a matrix and don't fight a `transform` from your CSS. Numbers mean px or deg |
| CSS properties, camelCase                            | `opacity`, `width`, `backgroundColor`, `filter`, `clipPath`, `boxShadow`… Bare numbers mean px, except unitless properties such as `opacity`                              |
| `'--custom-properties'`                              | Including greese ui tokens: animate `--greese-color-primary` and every component that reads it follows                                                                    |
| `text`                                               | Counts between numbers (`'0'` → `'12480'`), types on or deletes, or retypes, in the element's text nodes: markup inside (links, emphasis) stays                           |
| SVG attributes the element has                       | `r`, `cx`, `d` (when point counts match)…                                                                                                                                 |
| Numeric element properties                           | `scrollTop`, `scrollLeft`                                                                                                                                                 |
| Any object property                                  | Canvas, WebGL or game state your code reads each frame                                                                                                                    |

**How values interpolate:**

- **Numbers inside strings** interpolate when both ends have the same shape:
  `blur(0px)` → `blur(8px)`, `inset(0 0 0 0)` → `inset(0 50% 0 0)`.
- **A bare `0`** takes the other end's unit.
- **Different units blend exactly:** `16px` → `2rem`, `0px` → `50%`,
  `100px` → `50vw`, `200ms` → `1s`. Each number with a different unit
  becomes `calc(16px * 0.75 + 2rem * 0.25)` mid-way, which the browser
  resolves where the value is used, so percentages and viewport units are
  right for that element, with no measuring. The ends are written plainly.
- **Colors** mix in OKLab, so midpoints stay vivid, not muddy.
- **Anything else** switches halfway, except `none`/`hidden`, which give way
  to the shown value for the whole animation, as CSS does for `display`.

### Text

```ts
const { elements, revert } = splitText(heading) // or { by: 'words' }
timeline().from(elements, { opacity: 0, y: 12, stagger: 0.03 })
```

Each text node is split where it is, so markup inside stays: a link is still
a link, focusable and clickable, with its pieces inside it. The pieces are
hidden from assistive technology, and each text node's text is kept once
beside them, visually hidden, so screen readers read words, not letters.
Characters stay grouped per word, so lines still wrap normally. `revert()`
puts the original nodes back.

`text` works in the text nodes too. Typing on fills them in reading order,
each up to its own length, so the markup appears as it goes:

```ts
// <p>Read <a href="/docs">the docs</a> first</p>
timeline().fromTo(p, { text: '' }, { text: p.textContent!, duration: 1.2 })
```

A value of another shape is laid over the same lengths, so count on the
element that holds the number (`<strong>0</strong> items`: animate the
`strong`).

## Eases

| Ease                                                                        | Use                                              |
| --------------------------------------------------------------------------- | ------------------------------------------------ |
| `'out'` (default), `'in'`, `'inOut'`                                        | power2: a good general curve                     |
| `'power1'`–`'power4'`, `'sine'`, `'expo'`, `'circ'` + `.in`/`.out`/`.inOut` | Gentler to sharper curves                        |
| `'back.out(2)'`                                                             | Overshoots, then settles (the number is how far) |
| `'elastic.out(1.2, 0.4)'`                                                   | Springs (amplitude, period)                      |
| `'bounce.out'`                                                              | Bounces to rest                                  |
| `'linear'`, `'ease'`, `'ease-in-out'`, `'steps(4)'`                         | The CSS names                                    |
| `'cubic-bezier(0.2, 0, 0, 1)'`                                              | CSS's form, as easing tokens and styles write it |
| `[0.2, 0, 0, 1]` or a function                                              | Any cubic-bézier, or your own curve              |

Named eases use the common timeline names, so existing code ports directly.

## Playing Pixels animations: `fromPixels`

Animation authored in the Pixels studio can play on DOM elements, or any
targets. `fromPixels` reads a symbol animation's layers:

- keyframes and tweens become tracks on one timeline;
- frame numbers become seconds at the document's fps.

```ts
import { fromPixels } from '@greese/js'

const tl = fromPixels(
  doc.symbols.hero.animations.idle,
  {
    body: '.hero', // layer id → targets
    shadow: '.hero-shadow',
  },
  { channels: { glow: '--glow' } }
)
tl.play()
```

| Pixels                                                     | greese.js                                                               |
| ---------------------------------------------------------- | ----------------------------------------------------------------------- |
| Channels `x`, `y`, `scaleX`, `scaleY`                      | The same transform properties                                           |
| `rotation` (shortest arc, unless the tween disables it)    | `rotate`                                                                |
| `alpha`                                                    | `opacity`                                                               |
| Any other channel                                          | The same name: map it with `channels` (e.g. to a CSS variable)          |
| Frame index at `fps`                                       | Seconds = frame ÷ fps                                                   |
| `linear`, `easeIn`/`easeOut`/`easeInOut`, `bezier`, `step` | `linear`, the CSS `ease-*` curves, the bézier, `steps(1)`               |
| `elastic`, `bounce`, `back`                                | `elastic.out`, `bounce.out`, `back.in`, as every Glop studio draws them |
| Keys with no tween between them                            | A hold until the next key                                               |
| `loop`                                                     | `repeat: -1`                                                            |

Spans (nested animations) aren't read; nest timelines with `add()` instead.

## Editor tween names: `tweenEase`

An editor's tweens (authoring's `TweenType`, and the names saved rigs, sound
documents and game code hold) are named differently from greese.js's eases.
`tweenEase` draws them, so the curves are defined once, here (ADR 0040):

```ts
import { tweenEase, tweenEaseName } from '@greese/js'

tweenEase('easeOut')(0.5) // 0.75: quadratic
tweenEaseName('back') // 'back.in'
tweenEaseName('easeIn', { keywords: 'css' }) // 'ease-in', as Pixels draws it
tweenEaseName('bezier', { bezier: [0.7, 0, 0.84, 0] }) // the points
```

| Tween name                                                    | greese.js                                       |
| ------------------------------------------------------------- | ----------------------------------------------- |
| `linear`; `step`, `stepped`                                   | `linear`; `steps(1)`                            |
| `easeIn`, `easeOut`, `easeInOut` (and `easeInQuad` and so on) | `power1.in`, `.out`, `.inOut`; CSS's with `css` |
| `elastic`, `bounce`, `back`                                   | `elastic.out`, `bounce.out`, `back.in`          |
| `bezier`                                                      | The tween's points, or CSS `ease`               |
| A greese.js name (`power3.out`)                               | Itself                                          |
| Anything else                                                 | `linear`, so a saved document always loads      |

## Accessibility: reduced motion

When the user asks for reduced motion (`prefers-reduced-motion: reduce`), a
timeline jumps straight to its end when played. The final state still applies;
only the movement is skipped. For motion that carries meaning, such as a
progress indicator, opt out per timeline:

```ts
timeline({ reducedMotion: 'ignore' })
```

## Performance

greese.js samples values on the main thread, once per frame, through a single
shared `requestAnimationFrame` loop that runs only while something plays. It
batches each element's writes, so a frame does one style write per property.
It reads computed styles only once per property, for the starting value, and
never during playback.

- Prefer `x`/`y`/`scale`/`rotate` and `opacity` over `width`, `top` or
  `margin`: the browser can then skip layout.
- For long-running decorative loops, CSS `@keyframes` costs less: it runs off
  the main thread.
- Starting values are read once, the first time a property is sampled. After
  the page changes underneath (a resize), call `invalidate()`.
- Every write waits until its timeline has finished reading, and each frame
  renders all playing timelines in one batch, so reads never interleave with
  writes. When you start many animations at once outside a frame, wrap them
  in `batch()` for the same effect:

```ts
import { animate, batch } from '@greese/js'

batch(() => {
  for (const card of cards) animate(card, { opacity: [0, 1], y: [16, 0] })
})
```

## Porting timeline code

Timeline code ports directly: `to`, `from`, `fromTo`, `set`, `add`,
`call` and labels, the position syntax, `stagger` (a number,
`{ each, from }` or a function), function-based values and the named eases
are all the same. Keep a timeline and
call `kill()` to stop and restore what it animated. Plugins, scroll-driven
triggers, path motion and morphing aren't included.

The model follows the Pixels timeline: per-property keyframe tracks
sampled purely by time, nested timelines mapped through repeat and time scale
(Pixels' spans), and OKLab color mixing (Pixels mixes in OKLCH).
