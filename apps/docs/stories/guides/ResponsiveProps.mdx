# Responsive props

Layout and visual props take one value, or a value per breakpoint. Mobile-first: each
value applies from its breakpoint upward until a larger one overrides it.

```tsx
<Stack direction={{ xs: 'column', md: 'row' }} gap={{ xs: 2, lg: '2.5rem' }} />
<Grid container columns={{ xs: 1, sm: 2, lg: 4 }} gap={4} />
<Box p={{ xs: 4, md: 6 }} display={{ xs: 'none', md: 'block' }} />
<Button fullWidth={{ xs: true, md: false }}>Save</Button>
```

| Breakpoint | `xs` | `sm`  | `md`  | `lg`   | `xl`   |
| ---------- | ---- | ----- | ----- | ------ | ------ |
| min-width  | 0    | 600px | 900px | 1200px | 1536px |

## How it stays fast

No CSS is generated at runtime. Each breakpoint's value becomes one **class**:
a pre-generated one for scale tokens and enums, or a value class that reads an
**inline custom property** for any other length. Each class sets the property
directly, inside its breakpoint's media query:

```css
.greese-Stack--xs-gap-2 {
  gap: var(--greese-space-2);
}
@media (width >= 900px) {
  .greese-Stack--md-gap-4 {
    gap: var(--greese-space-4);
  }
  .greese-Stack--md-gap {
    gap: var(--greese-stack-gap-md);
  } /* gap={{ md: '13px' }} */
}
```

Larger breakpoints come later in the stylesheet, so they win where they apply,
and a smaller breakpoint's value carries on above it until one does. A prop
you don't set adds nothing to the element at all.

## Beyond the viewport

- **Container queries**: `<Grid container containerQueries>` makes its cells' `size`s respond to the grid's
  own width, so the same grid adapts in a sidebar and on a full page.
- **Intrinsic layout**: `<Grid container minChildWidth="14rem">` fits as many columns as there is
  room for, with no breakpoints at all.
- **Show / Hide**: `<Show above="md">` toggles with CSS, so no hydration mismatch.
- **When the tree must change** (not just its styles), use `useBreakpoint()`,
  `useBreakpointValue()` or `useMediaQuery()`.
