# Test audit, 2026-10-26

An audit of every test in the repository: repeated boilerplate that belongs in
shared modules, tests that check nothing new, tests that check how something
is built instead of what it does, and tests that can fail for reasons
unrelated to the code. The rules that came out of it are in the
[testing guide](README.md); this file records what was found, and where.

## What was audited

| Layer           | Files     | Tests                                          | Wall time (local)                           |
| --------------- | --------- | ---------------------------------------------- | ------------------------------------------- |
| Unit (Vitest)   | 55        | 858                                            | 1m 26s across the six packages, run in turn |
| e2e, playground | 14 specs  | 113 tests × 5 projects = 565 runs              | not timed here                              |
| e2e, site       | 4 specs   | 21                                             | not timed here                              |
| Visual          | 1 spec    | 298 stories × 2 schemes × 2 viewports = 1,192  | not timed here                              |
| Lighthouse      | 2 configs | 9 playground pages + the homepage, 3 runs each | not timed here                              |

The timings come from the test dashboard (`npm run test:dashboard`). Every
unit file and every spec was read.

**Overall:** the suite is in good shape. Test names describe behaviour, queries
are mostly by role and name, pure helpers are exported and tested directly,
and nothing is skipped. The issues below are about cost and upkeep, not
missing coverage.

## 1. Boilerplate to move into shared modules

### e2e: one support module for the playground specs

The same small helpers are written again in most spec files, each a little
differently:

| Helper                              | Copies                                                                                                                                                                                                                                 |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Read computed styles from a test id | `style` (content.spec.ts:9), `css` (layout.spec.ts:11), `styleOf` (motion.spec.ts:9), `style` (greese-prop.spec.ts:13), `read` (theming.spec.ts:23), and ~30 inline `getComputedStyle` evaluates                                       |
| Bounding box by test id             | additions.spec.ts:10, layout.spec.ts:17                                                                                                                                                                                                |
| "Is the viewport md or wider?"      | `wide` with a hard-coded 900 in additions.spec.ts:9, gaps.spec.ts:9, overlays.spec.ts:10, scrollbars.spec.ts:15; `WIDTHS` copied from the breakpoints in layout.spec.ts:7                                                              |
| "Is this a touch project?"          | four different ways: the `isMobile` fixture (content, additions, greese-prop), project-name lists (forms.spec.ts:12, overlays.spec.ts:9), `project.use.hasTouch` (catalogue.spec.ts:9), `project.name === 'iphone'` (gaps.spec.ts:121) |
| `#rrggbb` → `rgb()`                 | theming.spec.ts:5, vanilla.spec.ts:4                                                                                                                                                                                                   |
| Open a fixture page and wait for it | a `beforeEach` with `goto('/?page=…')` and a `waitFor` in 11 specs                                                                                                                                                                     |

**Do:** add `apps/playground/e2e/support.ts` with `openFixture(page, name,
ready)`, `computed(locator, ...props)`, `box(locator)`,
`atLeast(page, 'md')` reading the breakpoints from `@greese/ui` instead of
copying them, one `isTouch(testInfo)` based on `hasTouch`, `rgb(hex)`, and
`settled(locator)` (below). The site specs have one helper of their own
(`open` in componentScss.spec.ts:4) and can share the module where it fits.

### Unit (React): fakes and timers

| Boilerplate                                                                                                                                                                                  | Where                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A fake `IntersectionObserver` that captures callbacks                                                                                                                                        | three versions: catalogue.test.tsx:559, motion.test.tsx:30, scope.test.tsx:114                                                                                             |
| `vi.useFakeTimers({ toFake: ['requestAnimationFrame', 'cancelAnimationFrame', 'performance'] })`, then advancing one last frame after cleanup so the shared ticker doesn't stall later tests | six times in motion.test.tsx (lines 225, 274, 333, 474, 494, 523), with the last-frame flush repeated at 487 and 530                                                       |
| `render(…)`, then `await expectNoAxeViolations(container)` at the end                                                                                                                        | 54 times; several tests exist only to render a second copy of a tree the test beside them renders, for axe (Indicator, catalogue.test.tsx:75; Motion, motion.test.tsx:199) |

**Do:** add `src/test/intersection.ts` (one fake with `scrollIntoView(ratio)`),
`src/test/frames.ts` (`fakeFrames()`, which installs the fake clock and
flushes the last frame in its own `afterEach`), and fold the separate axe-only
tests into the behaviour test that already renders the same tree.

### Unit (SCSS): one compile helper

`compile = (scss) => compileString(…, { loadPaths, importers }).css` is
defined four times with slightly different options: kit.test.ts:19,
entryPoints.test.ts:10, breakpoints.test.ts:9 and
packages/react/src/utils/responsiveMixin.test.ts:10 (which reaches into
`../../../ui/src/styles/` by a relative path).

**Do:** export one `compileScss(scss, { use, breakpoints })` from a test-only
module in `@greese/ui` (`src/test/sass.ts`) and use it in all four.

### Reading built files

Five tests read `dist/` output by relative path, and motion.test.tsx:428 by a
path relative to the process's working directory (`'../ui/dist/css/Motion.css'`),
so it only passes when Vitest runs from `packages/react`. A stale `dist/` also
makes them test the last build instead of the source.

**Do:** resolve built files through the package (`import.meta.resolve('@greese/ui/css/Motion.css')`)
in one helper, and keep these tests few: turbo already builds dependencies
before `test`, but a local `npx vitest run` doesn't.

| Test                                                                                                                                     | Time          | Overlap                                                                                                                  |
| ---------------------------------------------------------------------------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| copySource.test.ts:95 "compiles for every component the library styles"                                                                  | 14.3 s        | Compiles each component in its own kit compile; one spec with every component would compile the kit once                 |

compiles every stylesheet and can fail on a stale `_manifest.scss` (or have
the test read `dist/css` instead of recompiling); keep one compiler-parity
test. Together this would take the site and ui unit runs from about 29 s each
to under 15 s.

## 3. Tests of implementation, not outcome

In this library some internals are deliberately public. The classes,
`data-*` attributes and per-instance custom properties a component renders
are the contract every framework package and plain HTML share (ADR 0014), so
unit tests that assert `greese-Button--outline` or `--greese-box-p-md` test
the API, not the implementation. Those stay. The ones below don't:

| Test                                                                                                                                                     | Problem                                                                                              | Do                                                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| motion.test.tsx:436 and :453 call `addMotion()` from `Motion/greeseRuntime.ts` with five positional arguments                                            | A private function's signature; any refactor of the runtime breaks them while behaviour is unchanged | Test through the `greese` prop or `resolveGreese`, as the rest of the file does |
| motion.test.tsx:270 `observers.every((o) => o.disconnected)`                                                                                             | Checks that the observer disconnected, not that the reveal happens once                              | Scroll out and in again and check it doesn't replay                             |
| motion.test.tsx:79–119 and :339 `toEqual` on the whole `className` string                                                                                | Fails on a reordering or an added class that changes nothing                                         | `toHaveClass(...)` or `toContain` for the classes that matter                   |
| gaps.spec.ts:132 `drawer.style.translate === ''`                                                                                                         | Checks how the snap-back is done                                                                     | Check the drawer's box is back where it started                                 |
| catalogue.spec.ts:91 Diff `clipPath` matches `/inset\(/`                                                                                                 | Passes for any inset, so it proves little                                                            | Check the clip edge sits at the divider's position, as the comment says         |
| e2e selectors on internal parts: `.greese-ScrollCarousel-viewport`, `.greese-Diff-handle`, `.greese-OtpField-slot`, `.greese-Rating-items`, `.hook-item` | Acceptable (parts are public classes), but a role or test id survives restructuring better           | Prefer roles; use part classes only where nothing else names the element        |
| Exact `className` equality: catalogue.test.tsx:182, content.test.tsx:663, overlays.test.tsx:233, layout.test.tsx:24                                      | Meant as "adds no modifiers"; fails if an always-on class is ever added                              | Assert the modifiers that must be absent instead                                |

## 4. Fragile tests

### Fixed sleeps (`waitForTimeout`)

Eleven calls in five specs wait a guessed time for a transition or a drag to
finish. They pass on a quiet machine and fail under load, or waste time
everywhere else:

- overlays.spec.ts:82, scrollbars.spec.ts:36, gaps.spec.ts:127 and :130: wait
  400 ms or 300 ms for a drawer to slide in or snap back.
- content.spec.ts:76, greese-prop.spec.ts:62, :88, :125, :150, :155: wait
  for a hover lift, a reveal or a settle.
- gaps.spec.ts:112: paces a drag at 40 ms a step so it isn't read as a flick.

**Do:** wait for the thing itself. A `settled(locator)` helper can await every
running animation and transition on the element
(`el.getAnimations({ subtree: true })`, then each one's `finished`); for "it
must not change", poll for a fixed number of frames with `expect.poll` and
`toPass`. The drag pacing is legitimate (it simulates a slow hand), but should
be expressed with `steps` instead of real time where the engine allows.

### Real-clock timing

motion.spec.ts:55 asserts a 0.25 s animation finishes in under 900 ms of wall
time. Under a parallel run on CI this is the most likely flake in the suite.
**Do:** check `time()` and `progress()` after playback (already done) and drop
the wall-clock bound, or keep it with a generous bound and say why.

### Hard-coded token values

e2e tests assert resolved pixel values that are really token values:
layout.spec.ts (`13px`, `32px`, `8px`, `16px`), content.spec.ts:46 (heading
sizes 56/44/36), additions.spec.ts:34 (gap 12, "space-3"), vanilla.spec.ts:22
and theming.spec.ts:34 (radius `8px`). A token change then fails tests whose
subject isn't the token. theming.spec.ts and vanilla.spec.ts already do the
right thing for colors by importing them from `@greese/ui`.

**Do:** read expected values from the token exports (`space`, `radius`,
`typography`) the same way.

### Snapshot-free but format-bound

responsiveMixin.test.ts and kit.test.ts match compiled CSS with regular
expressions that include Sass's whitespace (`\{\s+gap: …`). Sass's output
format is stable, so this is low risk; prefer `toContain` on a normalised
declaration where a regex isn't needed.

## 5. Priorities

1. **Remove the duplicates in section 2** (minutes; cuts about 15 e2e runs and
   most of the SCSS compile time).
2. **Replace the fixed sleeps and the real-clock bound** (section 4), the
   likeliest source of flakes.
3. **Add the e2e support module and the React test helpers** (section 1), then
   move the specs onto them as they're touched.
4. **Rewrite the implementation-bound tests** in section 3.
5. **Read token values from `@greese/ui`** in the e2e tests.

## Progress

**2026-10-27: duplicates and sleeps.**

- Deleted the e2e duplicates of unit tests: priority images, theme CSS
  injected once, the date field and the number field (four tests, 20 runs).
  The slider e2e test keeps its real-keyboard check and drops the inline
  variable the unit test already asserts.
- copySource.test.ts and componentStyles.test.ts compile every component in
  one theme, falling back to one at a time only to name a failure: 14.3 s and
  1.3 s down to under 1 s together.
- Folded the Indicator and Motion axe-only tests into the behaviour tests
  beside them.
- Replaced every fixed sleep with a wait on the state, through
  `apps/playground/e2e/support.ts`: `settled()` (no change to the box,
  transform or opacity for a number of frames, which covers CSS and greese.js
  motion), `leaves()` and `frames()`. The drawer's snap-back now checks where
  the drawer is, not its inline style. The one `waitForTimeout` left paces a
  simulated drag, so the drawer reads it as slow; it is input, not a wait.
- The wall-clock bound in motion.spec.ts is gone: the test drives the page's
  clock (`page.clock`, paused), so time scaling is checked against frames of a clock the test advances.

**2026-10-27: shared helpers, implementation-bound tests, token values.**
